# 飞书网盘同步流程

## 前置检查

1. 确认当前用户授权上传本项目资料。延续已有授权，不重复索取；用户仅允许本地时停止此步骤。
2. 优先发现已连接的飞书网盘工具，读取其说明，再只读检查登录身份、可访问的目标文件夹与权限。不得以桌面客户端存在或历史成功代替验证。
3. 优先使用已核实并记录的目标文件夹 ID／链接。没有目标时询问一次；不猜测用户账号、团队或根目录。
4. 无可用连接时状态为“待连接”；目标未知为“待指定目标”；无法核实权限为“权限未验证”。不自动安装、修改配置、索取明文令牌或绕过权限。

## 上传与校验

- 先列出目标已有文件，对照本地相对路径、字节数和可用哈希或版本信息。相同且可验证时跳过；同名不同内容创建版本，不覆盖或删除。
- 在已授权目标下使用项目名称子目录，保留本地目录关系。上传原始文件，不能仅贴文字到飞书文档而声称原文件已归档。
- 优先按目录逐文件保存。若只能打包则说明交付方式、记录包内清单和逐文件哈希；不得假装逐文件上传。
- 每个成功项记录相对路径、远端 ID、链接、大小、上传时间、核验方式；失败项记录原因与可重试项。
- 上传后重新列出或读取远端元数据并核对全部应上传文件。哈希不可用时记录实际使用的核验方式，不声称字节级校验成功。
- 同步记录作为本地控制文件，排除在必需上传清单和自引用哈希之外；如额外上传其快照，清楚注明快照时间。
- 只有清单全部核对成功才记“已同步”；部分成功为“部分同步”，失败为“同步失败”。本地归档状态不因云端失败丢失。

## 本地同步记录字段

项目、版本、目标链接／ID、检查时间、账号标识（最小必要）、本地状态、云端状态、应上传清单、成功清单、失败／待补清单、逐项核验依据。
每次重试先核对远端状态，避免重复上传。不得创建无人值守定时同步任务，除非用户另行要求。

## CLI 执行与回读

读取 lark-shared、lark-drive；原生 Markdown 使用 lark-markdown 的 `markdown +create`，其他文件使用 `drive +upload`。先查对应 reference / --help，不猜参数。路径参数使用 cwd 下的相对路径；所有用户网盘请求显式 `--as user`。身份核验成功后，按用户本地控制记录中已授权的目标 token 列取目录；分页直到 has_more=false，缺失 continuation token 视为未完成。
上传前生成不可变的本批路径、字节数和 SHA-256 清单。排除凭证、.git、缓存、本地控制记录和回读目录；不可仅靠扩展名判断敏感信息。
上传后 `drive +download --file-token <token> --output <新的相对回读路径>`，下载到独立临时目录，核对字节数与 SHA-256；回读不能覆盖源文件。若只能预览、导出或元数据校验，标记“字节级回读未验证”，不得把转换后的内容等价为原文件一致。
所有项必须重新列取确认父目录、名称、token，且回读哈希一致，才可记“已同步且回读验证通过”。列取成功仅能记“目录清单核对通过”。

## 幂等与失败恢复

以项目身份、版本、本地相对路径、SHA-256 标识归档项。清单覆盖全部应上传文档及成果（不包含清单自身和控制记录）；状态至少含 planned/uploaded/verified/failed/uncertain。
- 本地：相同版本与内容只验证并跳过；内容变化新增版本目录；无法确认同名项目身份则停止，不合并。目录锁防止并发；残留锁先检查进程，不能自动删除。生成文件先写临时目录，验证后发布到不存在的目标。
- 远端：逐层列取、复用唯一且身份匹配的项目目录。出现多个同名候选停止并记录歧义。逐文件已有 token 时先回读，哈希一致直接跳过；不同内容创建新版本目录，禁止覆盖。
- 上传返回成功后立即原子更新本地控制记录，再回读；若超时或进程中断，标记 uncertain。恢复先列取目标并回读候选，确认无同内容文件后才重新上传，不能盲目重试写请求。
- 网络暂时故障和限流最多重试 3 次，按 2/4/8 秒或 Retry-After 退避；权限、scope、目标不存在、钥匙串错误停止对应同步。退出码 10 按 lark-shared 门禁处理。
- 部分失败保留全部本地资料和已验证 token，逐项报告。不得因云端失败移动、删除本地归档，也不得清理已上传文件来“回滚”。
- 控制记录只存最小账号标识、目标、清单摘要、逐项 token/链接/大小/哈希/时间/错误及核验依据，不存 access token。控制记录用临时文件加原子替换更新；不改历史版本。
